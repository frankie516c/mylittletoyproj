# ksent — 한국어 감성분류 모델을 믿을 수 있나

허깅페이스의 한국어 감성 모델 3종이 **어디서 무너지는지** 찾아낸 평가 하네스입니다.
모델을 만드는 작업이 아니라, 남이 만든 모델을 깨뜨려서 한계를 문서화한 작업입니다.

> **한 줄 결론**
> 부정문·대조문은 진짜로 학습돼 있다. **반어법은 전혀 학습돼 있지 않고, 모델은 그 사실을 모른다.**
> 부정 처리는 TF-IDF 대비 +29%p 로 트랜스포머가 실제로 버는 구간이다. 반면 반어법은 정확도가
> 낮은 정도가 아니라 **다수클래스 베이스라인보다 낮고, 틀릴 때 확신도가 더 높다.**
> 확신도 임계값으로는 걸러낼 수 없다는 뜻이다.

전체 리포트는 [`report.html`](report.html) — 표와 그래프가 있어 브라우저로 열어야 합니다.
(GitHub 은 HTML 을 렌더링하지 않으니 내려받아서 열거나, 아래 요약을 보세요.)

## 검증 대상

트랜스포머만 줄세우지 않고 **위아래로 베이스라인을 깐 것**이 이 작업의 핵심입니다.
"트랜스포머가 어휘 통계 대비 실제로 무엇을 더 하는가"를 분리해서 볼 수 있습니다.

| | 모델 | 역할 |
|---|---|---|
| | `sangrimlee/bert-base-multilingual-cased-nsmc` | mBERT, NSMC 학습 |
| | `Copycats/koelectra-base-v3-generalized-sentiment-analysis` | KoELECTRA, 쇼핑리뷰 범용 |
| | `matthewburke/korean_sentiment` | KcELECTRA |
| | 3종 평균 앙상블 | |
| 상한선 | char 2-4gram TF-IDF + 로지스틱회귀 (NSMC train 150k) | **어휘 통계만으로 어디까지 되는가** |
| 바닥선 | 규칙 기반 감성사전 | |

## 3부 구성

**A. NSMC held-out 벤치마크** (5,000건) — 정확도·F1·AUC 뿐 아니라 **보정**(Brier, ECE/MCE, 온도
스케일링)과 **선택적 예측**(위험-커버리지 곡선, AURC), 모델 간 유의성까지 봅니다.
"정확도는 같은데 확률을 믿을 수 있느냐"가 갈리는 지점입니다.

**B. 행동 테스트 스위트** (CheckList 스타일, 202케이스) — 직접 만든 문장으로 능력을 쪼개 측정합니다.

- `MFT` Minimum Functionality — 텍스트 + 정답 라벨
- `INV` Invariance — 의미를 바꾸지 않는 변형 후에도 예측이 유지되는가
- `DIR` Directional — 변형 후 P(pos) 가 기대한 방향으로 움직이는가
- `UNC` Uncertainty — 정답이 없는 중립문에서 확신도가 낮아지는가

14개 능력군 × 난이도 3단계로 태깅되어 있습니다.

**C. 편향·일관성 프로브** — 인물명·장르명을 치환하면 예측이 흔들리는지, 의견과 무관한 문맥을
앞뒤에 덧붙이면 라벨이 뒤집히는지.

## 발견

### F01 (치명) 반어법에서 세 모델 모두 다수클래스 베이스라인보다 못한다

반어 26케이스(반어적 비난 20 / 반어적 칭찬 6)에서 **mbert .54, koelectra .50, kcelectra .35**.
"무조건 부정"을 찍으면 **.77** 입니다. 표면 어휘를 그대로 따라가며, 문장 후반부가 앞부분을
뒤집는 구조를 읽지 못합니다.

| 문장 | 정답 | mbert / koelectra / kcelectra |
|---|---|---|
| "명작이네요 명작. 화장실 갈 타이밍 잡기 딱 좋은." | 부정 | 0.96 / 0.98 / 0.97 |
| "돈 아깝네요. 티켓값이 이 퀄리티에 비해 너무 쌉니다." | 긍정 | 0.00 / 0.00 / 0.05 |
| "최악입니다. 이걸 보고 나니 다른 영화가 다 시시해졌어요." | 긍정 | 0.00 / 0.02 / 0.04 |

### F02 (치명) 틀릴 때 더 확신한다 — 확신도 필터링이 통하지 않는다

행동 테스트 오답 중 확신도 0.9 초과 비율: **koelectra 55%, kcelectra 56%, mbert 34%.**
얕은 TF-IDF 베이스라인은 **12%** 입니다. 트랜스포머는 어려운 케이스에서 조용히 애매해지는 게
아니라 **자신 있게 틀립니다.** "확신도 0.9 미만은 사람이 검수" 같은 운영 규칙으로 F01 을 막을 수
없습니다.

다만 3종 평균 앙상블은 이 비율을 **24%** 로 떨어뜨립니다. 모델 간 불일치가 난이도 신호로
작동하기 때문이고, 실무에서 유일하게 값싼 완화책입니다. 비용은 추론 3배.

### F03 (중대) P(positive) 는 감성 "강도"가 아니다 — 별점 추정에 쓸 수 없다

부정 뒤집기에는 완벽히 반응하지만(Δ≈−0.94) 강도 변화에는 거의 반응이 없습니다.
확률이 0.97~0.99 에 포화된 **이진 스위치**입니다.

| 변형 | 기대 | mbert / koelectra / kcelectra |
|---|---|---|
| "재미있었다" → "정말 너무 재미있었다" | 상승 | +0.010 / +0.018 / −0.000 |
| "지루했다" → "너무너무 지루했다" | 하락 | +0.000 / +0.003 / +0.000 |
| "괜찮은 영화였다" + "다만 결말이 많이 아쉬웠다" | 하락 | +0.002 / −0.018 / −0.012 |
| "재미있었다" → "재미없었다" | 하락 | −0.978 / −0.959 / −0.937 |

긍정 문장에 불만 절을 덧붙여도 확률이 내려가지 않는 점이 특히 위험합니다.

### F04 (중대) 무관한 문맥을 덧붙이면 mbert·kcelectra 는 30% 가 뒤집힌다

의견과 무관한 문장("어제 친구랑 같이 극장에서 봤습니다", "참고로 주차는 3시간 무료였습니다")만
앞뒤에 붙였는데 라벨이 바뀝니다. koelectra 는 3.0% 로 뚜렷하게 강건합니다.

### 능력군별 정확도 (일부)

| 능력군 | n | mbert | koelectra | kcelectra | TF-IDF | 사전 |
|---|---|---|---|---|---|---|
| 이중부정 | 16 | .56 | **1.00** | .88 | .50 | .81 |
| **반어법** | 26 | **.54** | **.50** | **.35** | .50 | .27 |
| 부정 | 24 | .88 | .96 | .92 | .67 | .33 |
| 대조(~지만) | 20 | .95 | 1.00 | .95 | .70 | .55 |
| 인용된 의견 | 16 | .81 | .94 | .94 | .88 | .62 |
| 적대적 어휘 | 16 | .81 | .88 | .94 | .62 | .44 |
| **전체** | **202** | **.797** | **.901** | **.876** | **.748** | **.554** |

NSMC held-out 정확도는 koelectra .924 / kcelectra .885 / mbert .872 / TF-IDF .871 입니다.
**mbert 와 TF-IDF 는 NSMC 점수가 거의 같지만 행동 테스트에서 5%p 벌어집니다** —
벤치마크 점수만 보면 안 되는 이유가 이 한 줄에 있습니다.

세 모델이 **전원 틀린 139건**을 하나씩 읽고 수동 판정했습니다 ([`adjudication.py`](adjudication.py)).

| 판정 | 건수 | |

| **M** 진짜 모델 실패 | 27 (19.4%) | 골드가 방어 가능하고 본문에 판정 가능한 의견이 있음 |

즉 "정확도 92%" 의 남은 8% 중 상당 부분은 모델 잘못이 아닙니다.

## 이 검증이 방어하는 것

- **라벨 극성 실측.** 허브의 `id2label` 을 믿지 않고 명백한 긍/부정 프로브 문장으로 방향을 직접
  측정합니다. 세 모델 모두 index 1 = 긍정, 분리도 0.94~0.99. kcelectra 는 `LABEL_0/LABEL_1` 로만
  표기돼 있어 **이 단계 없이는 극성을 뒤집어 쓸 위험**이 있었습니다. ([`predictor.py`](predictor.py))
- **유출 검사.** 수제 문장 210개를 NSMC train 150k / test 50k 와 대조했습니다. 정확 일치 15건은
  전부 "재미있었다" 류 짧은 상용구였고, **결론이 걸린 MFT 난이도 세트는 정확 일치 0건**입니다.
  스위트가 학습 데이터와 겹치면 행동 테스트가 아니라 암기 테스트가 됩니다. ([`check_leakage.py`](check_leakage.py))
- **다수클래스 베이스라인 병기.** 반어 세트가 부정 라벨로 치우치면 "무조건 부정" 모델이 만점을
  받으므로, 반어적 칭찬 6케이스를 넣어 .77 로 낮추고 모든 셀에 이 값을 함께 표기했습니다.
- **얕은 상한선.** NSMC train 150k 로 학습한 char n-gram TF-IDF 를 같이 돌려, 어휘 통계만으로
  도달 가능한 지점을 명시했습니다.
- **Wilson 신뢰구간**을 모든 셀에 병기했습니다. scipy 없이 순수 numpy/math 구현. ([`metrics.py`](metrics.py))

## 믿으면 안 되는 것

- **주석자가 1명입니다.** 202케이스의 정답과 139건 오분류 판정 모두 2차 검수를 받지 않았습니다.
  특히 판정 불가(U) 80건의 배분에 주석자 편향이 들어갈 수 있습니다. 원자료를
  [`results/cases.csv`](results/cases.csv) 와 [`adjudication.py`](adjudication.py) 에 남겨 재판정이 가능합니다.
- **소분류 표본이 작습니다.** n=6~26 이라 Wilson CI 가 ±0.2 에 이릅니다. 확실한 결론은
  반어(n=26, CI 상한도 다수클래스 미만)와 부정(n=24) 정도이고, 가정법(n=6)·장문(n=3)은 방향 참고용입니다.
- **NSMC 는 5,000건 부분표본입니다.** 전체 50,000건이 아닙니다 (CPU 추론 비용). TF-IDF 만 전체
  테스트셋을 돌렸고 0.8714 였습니다.
- **koelectra-gen 은 도메인이 다릅니다.** 쇼핑리뷰 기반 범용 모델이라 NSMC 기준으로는
  out-of-domain 인데도 1등입니다. 영화 전용 학습이 반드시 유리하지 않다는 뜻이지만,
  비교의 공정성 측면에서는 감안이 필요합니다.

## 범위 밖: LLM 비교

이 작업은 **"파인튜닝된 소형 분류 모델 3종 중 무엇을 쓸 것인가"** 에 답합니다.
Claude·GPT 같은 LLM 은 넣지 않았고, 넣을 계획도 없습니다 — 질문과 답이 이미 맞물려 있어서
LLM 을 끼워넣으면 무엇을 비교한 것인지 흐려집니다.

LLM 이 이 문장들을 어떻게 처리하는지는 분명 흥미로운 질문이지만, 그건 이 저장소의 다음 작업인
**RAG 평가**에서 다루는 게 맞습니다. 아래 계획을 보세요.

## 다음: dog-training-rag 평가에 어떻게 옮길 것인가

이 하네스의 **코드는 재사용할 수 없습니다.** [`predictor.py`](predictor.py) 는 "텍스트 하나 →
P(positive) 하나" 라는 이진 분류를 전제로 짜여 있고, RAG 는 검색 + 자유 텍스트 생성이라
출력 형태부터 맞지 않습니다.

**하지만 방법론은 그대로 옮겨갑니다.** 아래가 `dog-training-rag` 에 적용할 계획입니다.

### 타이밍이 핵심이다

dog-training-rag 는 현재 **검색 파이프라인이 미구현** 상태입니다. 평가 세트는 **구현 전에**
만들어야 합니다. 구현하고 나서 만들면 이미 내린 결정을 정당화하는 도구가 되지만, 먼저 만들면
"청크 크기 300 vs 800", "재전사 21시간치로 충분한가" 같은 질문마다 답이 나옵니다.

### 그대로 옮겨오는 것 3가지

| ksent 에서 | dog-training-rag 에서 |
|---|---|
| TF-IDF 상한선 | **검색 없는 LLM 단독** — "검색이 실제로 무엇을 더 버는가" |
| 유출 검사 | 평가 질문이 청크에 그대로 있으면 검색력이 아니라 완전일치 테스트 |
| 능력군 × 난이도 태깅 | 질문 유형별로 쪼개서 측정 |

가운데 줄이 특히 중요합니다. RAG 프로젝트 대부분이 **"RAG 없을 때보다 나은가"를 재보지
않습니다.** 베이스라인은 사다리로 놓습니다:

```
(a) 검색 없이 LLM 단독          ← 바닥선. 이걸 못 이기면 RAG 는 존재 이유가 없다
(b) BM25 키워드 검색 + LLM      ← 얕은 상한선. ksent 의 TF-IDF 자리
(c) 임베딩 검색 + LLM           ← 본 시스템
```

(b) 와 (c) 의 차이가 곧 임베딩이 실제로 버는 값입니다. (a) 와 (c) 가 비슷하면 이 도메인 지식이
이미 LLM 안에 있다는 뜻이고, 프로젝트 방향을 다시 잡아야 합니다.

### 질문 능력군 (초안)

`suite_data.py` 의 난이도 태깅 방식을 그대로 씁니다.

| 능력군 | 무엇을 보나 | 난이도 |
|---|---|---|
| 단일 청크 답변 | 한 영상에 답이 그대로 있는 질문 | 1 |
| 다중 영상 종합 | 여러 훈련사의 설명을 합쳐야 하는 질문 | 2 |
| **지식베이스에 없음** | **"모른다"고 답해야 하는 질문 — 환각 테스트** | 3 |
| 상충하는 조언 | 훈련사마다 의견이 갈리는 주제. 한쪽만 말하면 실패 | 3 |
| 범위 밖 | 의료·수의 영역. 거절하고 병원 안내를 해야 함 | 2 |

세 번째 줄이 이 평가의 핵심입니다. ksent 의 F02 를 그대로 옮기면 **"지식베이스에 없는 질문에
자신 있게 지어내는가"** 가 되고, 그게 RAG 에서 가장 위험한 실패입니다.

### 새로 필요한 것 (감성분류엔 없던 것)

1. **검색 품질과 생성 품질을 분리 측정.** `recall@k`(정답 청크가 상위 k 에 올라왔는가) 와
   `groundedness`(올라온 청크에 근거해 답했는가) 를 따로 재야 합니다. 합쳐서 재면 틀렸을 때
   **검색이 못 찾은 건지 생성이 무시한 건지** 알 수 없습니다.
2. **타임스탬프 정확도.** 이 프로젝트의 고유 목표가 "답변마다 원본 영상의 해당 시점을 되짚어
   주는 것"이므로, 되짚은 시점이 실제로 그 내용인지를 별도 지표로 재야 합니다.
3. **채점자 검증.** 자유 텍스트 채점은 LLM 심판을 쓰게 되는데, **심판 자체를 먼저 검증해야
   합니다.** 사람이 채점한 30~50건과 심판 점수의 일치도를 재고 시작합니다.
   ksent F02 의 교훈이 그대로 적용됩니다 — 검증되지 않은 확신도 숫자는 아무것도 보증하지 않습니다.

### 규모

능력군 5개 × 각 12~20문항 = **60~100 문항**이면 ksent 와 같은 수준의 Wilson CI 를 얻습니다.
ksent 의 반성 하나가 "소분류 n 이 작아 CI 가 ±0.2 였다" 였으므로, **만들기 전에 규모를 먼저
정합니다.**

### 착수 순서

1. 질문 30개 초안 (능력군 5개 × 6문항) + 정답·근거 영상/시점 태깅
2. [`check_leakage.py`](check_leakage.py) 방식으로 유출 검사 — 질문이 청크와 완전일치하지 않는지
3. **검색 없는 LLM 단독 베이스라인 측정** ← 이 숫자가 없으면 이후 모든 개선이 무의미
4. 검색 붙이고 재측정, (a)/(b)/(c) 사다리 비교
5. LLM 심판 vs 사람 채점 일치도 검증
6. 결론이 걸리는 능력군만 60~100문항으로 확장

### 곁가지: dog-trainer-demo 의 심판 점수

[`../dog-trainer-demo/`](../dog-trainer-demo/) 는 화면에 **신뢰도·정확성 점수를 0~100 으로
표시**하는데, 그 숫자를 LLM 심판이 매기고 있고 **실제 정답률과의 상관은 검증된 적이 없습니다**
(`server.js` 의 `/api/eval`). ksent F02 가 정확히 겨냥하는 형태입니다.
위 5번(심판 검증)을 할 때 같은 방법으로 함께 재보면 됩니다.

## 재현

```bash
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements.txt

# NSMC 데이터셋을 data/ 에 둔다 (저장소에 포함하지 않음, 19MB)
#   https://github.com/e9t/nsmc  ->  ratings_train.txt, ratings_test.txt

# 파트 A — 모델을 하나씩 로드/예측/해제한다 (동시 상주 시 CPU 추론 중 프로세스가 죽었음)
python run_nsmc.py predict mbert-nsmc
python run_nsmc.py predict koelectra-gen
python run_nsmc.py predict kcelectra-ko
python run_nsmc.py predict tfidf-lr
python run_nsmc.py report

# 파트 B, C — 행동 테스트 + 편향 프로브
python run_eval.py --n-nsmc 5000
python make_report.py            # results.json -> 요약 마크다운

# 임의 문장을 모든 모델에 던져보기
python probe.py "재미없지 않았어요" "그럭저럭 볼만했다"
```

예측 캐시(`results/*.npy`)를 커밋해 뒀으므로 **모델을 다시 돌리지 않고도**
`run_nsmc.py report` 로 파트 A 통계를 재생성할 수 있습니다.

## 파일 구성

```
run_eval.py          파트 B·C 총괄 (행동 테스트 + 편향 프로브)
run_nsmc.py          파트 A — 모델별 예측 캐싱 후 통계
predictor.py         모델 로딩 + 배치 추론 + 극성 실측 검증
suite_data.py        행동 테스트 스위트 본체 (14개 능력군)
suite_ext.py         검정력 보강용 추가 케이스 (import 시 자동 병합)
perturb.py           의미 보존 변형. 감성 어휘는 보호해서 라벨이 안 흔들리게 함
tfidf_baseline.py    얕은 상한선 — char n-gram TF-IDF + 로지스틱회귀
metrics.py           Wilson CI, 부트스트랩, ECE, AURC (순수 numpy)
check_leakage.py     수제 문장이 NSMC 에 이미 있는지 검사
adjudication.py      전원 오답 139건 수동 판정 원자료
probe.py             대화형 프로브
make_report.py       results.json -> 마크다운 요약
report.html          최종 리포트 (브라우저로 열 것)
results/
  results.json           파트 B·C 전체 결과
  nsmc_report_5000.json  파트 A 통계
  cases.csv              케이스별 원자료 2,138행 (재판정용)
  *.npy                  모델별 예측 캐시
  *.log                  실행 로그
```
