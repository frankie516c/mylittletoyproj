개인 토이 프로젝트 모음. **프로젝트 하나당 최상위 폴더 하나**로 관리합니다.

| 폴더 | 내용 | 스택 |
|---|---|---|
| [`dog-trainer-demo/`](dog-trainer-demo/) | 멍톡 🐩 — 말로 묻는 강아지 훈련 상담 데모. STT → 웹 검색 답변 → 신뢰도/정확성/속도 분석 | Node (무의존성), OpenAI API |

## 규칙

**폴더 구조** — 각 프로젝트는 자기 폴더 안에서 자족적이어야 합니다. 자체 `README.md`,
자체 `.gitignore`, 의존성 파일(`requirements.txt` / `package.json`)을 폴더 안에 둡니다.
서로 임포트하는 코드는 쪼개지 말고 한 폴더로 묶습니다.

**브랜치** — 프로젝트별 장수 브랜치를 만들지 않습니다. 브랜치는 "작업 중"이라는 뜻이지
칸막이가 아닙니다. 새 프로젝트나 수정은 `main` 에서 짧은 브랜치를 따서 → PR → 머지 →
브랜치 삭제. 전체 모습은 언제나 `main` 하나에서 보입니다.

**비밀정보** — 실제 키가 든 `.env` 는 절대 커밋하지 않습니다. 대신 플레이스홀더 값을 넣은
`.env.example` 을 커밋하고, README 에 `cp .env.example .env` 를 안내합니다.
루트 `.gitignore` 가 `.env` / 인증서 / 서비스 계정 키를 저장소 전체에서 막지만,
그건 마지막 그물일 뿐이니 **머지 전 PR diff 를 눈으로 확인**하는 습관을 들이세요.

**용량** — 모델 가중치·데이터셋·음성 샘플은 커밋하지 않습니다 (루트 `.gitignore` 에서 제외됨).
GitHub 은 100MB 넘는 파일을 거부하고, 한번 들어간 큰 파일은 히스토리에서 지우기가 번거롭습니다.
받는 방법을 README 에 적어두는 것으로 대신합니다.
