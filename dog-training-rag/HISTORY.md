## 3. 데모 구축

요청: 웹에서 훈련 자료를 마크다운으로 변환 → 마크다운 청킹 → 작고 성능 괜찮은 임베딩 모델 →
로컬 벡터 DB → OpenAI로 답하는 데모 웹사이트. 자료는 2페이지 정도만.

### 3.1 환경

`.venv`가 Python 3.14.7이고 **패키지가 하나도 설치돼 있지 않았다**. `uv`도 없었다.
(참고: `pyproject.toml`은 `>=3.12,<3.13`을 요구하지만 시스템에 3.14만 있음.)

설치: `fastapi uvicorn httpx trafilatura openai qdrant-client[fastembed]` — 10분 이상 걸려
백그라운드로 돌림. torch를 피하려고 sentence-transformers 대신 **fastembed(ONNX Runtime)** 선택.

### 3.2 소스 선정 (1차)

ASPCA tier-1 문서 2편. 어린 강아지 편과 성견 편을 짝으로 골라 "연령대에 따라 대응이 다르다"를
검색으로 구분할 수 있게 했다.

- `aspca-puppy-mouthing` — Mouthing, Nipping and Biting in Puppies (11,875자)
- `aspca-adult-mouthing` — Mouthing, Nipping and Play Biting in Adult Dogs (12,496자)

`trafilatura`로 보일러플레이트를 걷어내고 헤딩 구조를 보존한 마크다운을 뽑았다.

### 3.3 구조 인식 청킹

`demo/chunker.py`를 직접 작성. 헤딩 트리를 1차 경계로 쓰고, 짧은 섹션은 형제에 흡수,
긴 섹션은 문단/리스트 덩어리 경계에서만 분할. 임베딩 텍스트에 `[문서 > H2 > H3]` 컨텍스트
헤더를 붙이고 표시에는 본문만 쓴다.

작업 중 나온 실제 문제 2건:

1. **한 문단이 통째로 1,899자** — 상한 1,100자를 넘겼다. 문장 경계 폴백을 추가해 해결.
   (최대 1,899자 → 1,256자 = 상한 1,100 + 오버랩 160)
2. **헤딩 경로에 문서 제목이 중복** — 마크다운 H1이 문서 제목과 같아
   `제목 > 제목 > 섹션`이 됐다. 연속 중복 헤딩을 접도록 수정.

### 3.4 임베딩 모델 — 320MiB 스톨

`intfloat/multilingual-e5-small`(118M / 384d)를 골랐다. fastembed 기본 카탈로그에 없어
`add_custom_model`로 커스텀 ONNX 등록.

**fp32 ONNX(약 470MB)가 정확히 320MiB(335,544,320 바이트)에서 두 번 연속 끊겼다.**
무작위 실패가 아니라 결정적 패턴이었다. HF API로 리포 파일 목록을 조회해
`onnx/model_qint8_avx512_vnni.onnx`(int8 양자화, 약 118MB)로 전환해 다운로드 성공.

> 이 선택이 나중에 §6 성능 문제의 유력한 원인으로 지목된다.

### 3.5 OpenAI 키

`dog-training-rag/.env`의 `OPENAI_API_KEY`가 비어 있었다. 워크스페이스를 뒤져
**`dog-trainer-demo/.env`에 실제 키**가 있는 것을 확인하고 복사해 넣었다.
`DEMO_OPENAI_MODEL=gpt-4o-mini` 추가. `.env`와 `data/`는 이미 gitignore 대상이라
키와 벡터DB는 커밋되지 않는다.

### 3.6 1차 검증 (33개 청크)

| 질문 | 결과 |
|---|---|
| "강아지가 손을 자꾸 무는데…" | 단계별 방법 + `[2][4]` 인용, 체벌 금지 경고 자동 부착 |
| "언제 전문가를 찾아가야 하나요?" | CAAB / ACVB / CPDT 연계 안내를 근거에서 정확히 인용 |
| "고양이 화장실 훈련"(범위 밖) | "제공된 자료로는 답할 수 없습니다" — 정상 거부 |

검색 7ms / 생성 5.3초. 브라우저 확장이 연결돼 있지 않아 스크린샷 검증은 못 하고
HTTP 200 응답만 확인했다.

## 4. LangSmith 질문

"LangSmith로 구현했어?" — 아니오. LangChain 계열은 하나도 쓰지 않았다.
외부 패키지는 `trafilatura` / `fastembed` / `qdrant-client` / `openai` / `fastapi` / `uvicorn`
뿐이다. 프레임워크 미도입은 리서치 문서 `08-reference-architecture.md`의 결론을 따른 것.

LangSmith는 관측 도구라 애초에 범위 밖이었고, 리서치 문서는 관측용으로 Langfuse 셀프호스트,
개발 평가로 DeepEval+pytest를 권했다. 둘 다 골든셋이 있어야 의미가 있어 데모에서는 뺐다.

## 5. 코퍼스 확대

실사용 테스트에서 **"4살 된 푸들이 배변패드에 앞발만 두고 쉬를 했습니다"** 질문에
"답할 수 없다"가 나왔다. 코퍼스에 배변 훈련 자료가 아예 없어서 나온 정상 동작이지만,
데모로서는 쓸모가 없었다.

후보 URL을 실제로 페치해 검증한 뒤(13개 중 8개 성공, 5개는 404) 10편으로 재구성:

| 주제 | 문서 수 | 청크 |
|---|---|---|
| 배변 훈련 | 5 (AKC 3, HSUS 1, ASPCA 1) | 36 |
| 입질·물기 | 2 (ASPCA) | 33 |
| 짖음 | 1 (ASPCA) | 40 |
| 분리불안 | 1 (ASPCA) | 31 |
| 씹기·물어뜯기 | 1 (ASPCA) | 15 |
| **합계** | **10** | **155** |

재색인 후 해당 질문의 상위 5개 중 4개가 배변 훈련 문서로 바뀌었다. 다만 코퍼스에
"패드에 앞발만 올리는" 정확한 케이스를 다루는 대목은 없다(패드 크기 조절 언급만 있음).

### 5.1 중단된 작업

서버에 **질의 로그(JSONL)와 커버리지 표시**를 추가하는 재작성을 시도했으나
bash heredoc 파싱 오류로 실행되지 않았다. 이후 사용자가 중단을 요청해 되돌리지 않았다.
따라서 `demo/server.py`는 이 기능들이 **없는 상태**이고, `demo/web/index.html`의 예시 질문도
입질 중심 그대로다.

대신 "4살 푸들 배변패드" 질문에는 직접 답변했다 — 조준(targeting) 문제로 진단하고,
의학적 원인 확인 → 환경 원인별 조치표 → 2~3주 재훈련 절차 → 실수 처리 순으로 정리.

## 6. 검색 평가

요청: 청크 10개를 무작위로 뽑아 각각에 대한 질문을 만들고, 평가 데이터로 저장한 뒤
**검색 기능만** hit rate와 MRR로 측정.

### 6.1 평가셋 생성 (`demo/make_evalset.py`)

- 155개 중 300자 이상인 147개를 풀로 삼아 seed 42로 10개 표본 추출
- 각 청크에 대해 gpt-4o-mini가 "이 조각을 읽어야만 답할 수 있는 자연스러운 한국어 질문" 1개 생성
- `data/demo/eval/golden_v1.jsonl`에 질문 + 정답 청크(doc_id, chunk_index) 쌍으로 저장

### 6.2 측정 결과 (`demo/evaluate.py`, 생성 호출 없음)

| 지표 | 값 |
|---|---|
| hit rate@1 | 0.000 (0/10) |
| hit rate@3 | 0.000 (0/10) |
| hit rate@5 | 0.100 (1/10) |
| hit rate@10 | 0.500 (5/10) |
| MRR@10 | 0.087 |

155개 청크 코퍼스에서 이 정도면 검색이 사실상 작동하지 않는 수준이다.

### 6.3 원인 진단

"@1이 너무 빡센 것 아니냐"는 지적에 따라 기준을 완화해 다시 측정:

| 단위 | @1 | @5 | @10 |
|---|---|---|---|
| 청크 | 0/10 | 1/10 | 5/10 |
| 문서 | 4/10 | 8/10 | 9/10 |
| 주제 | 5/10 | — | — |

라벨 완화로 일부 설명된다 — 같은 문서의 옆 청크가 똑같이 답이 되는데 평가셋은
"이 청크 하나만 정답"으로 보기 때문이다. 하지만 문서 단위 @1이 4/10인 건 여전히 나쁘다.

추가 진단:

1. **파이프라인 버그 아님** — 정답 청크 본문을 그대로 질의로 넣으면 자기 자신을 9/10 찾아온다.
   (실패한 1건은 ASPCA 퍼피 편과 성견 편에 거의 동일한 문장이 있어서다.)
2. **점수 폭이 top-20 전체에서 0.0125** — 1위 0.8040 / 5위 0.7970 / 20위 0.7915.
   임베딩이 모든 청크에 사실상 같은 점수를 주고 있어 순위가 노이즈다.
   앞서 "고양이 화장실 훈련"이 0.79로 나온 것과 같은 증상.

**유력한 원인: §3.4의 int8 양자화.** 확인을 위해 `demo/compare_models.py`(양자화 vs O4 vs
MiniLM 비교)를 작성했으나 **실행 전에 중단**했다.
